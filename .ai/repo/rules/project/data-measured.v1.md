# Rationale

A personal site that says "evidence over claims" cannot itself claim. Hand-typed numbers go
stale silently; a measured snapshot with a date stays honest even when it ages.

# Required behaviour

- `data/projects.toml` holds words only: name, tagline, summary, category, URL, stack. Majordomus
  supervision is never listed in `stack`; it is measured: the `[supervision] marker`
  (`.ai/manifest.yaml`) on the default branch, declared once and asked through one connection to
  every forge (`scripts/lib/forge.mjs`: `gh` for GitHub, the shared GitLab client for GitLab), the
  forge, owner and name inferred from each repository's URL.
- Every original repository in `data/index.json` carries `supervised` (true, false, or null when
  no forge could answer), `counts.supervised` and `supervision` (marker, measured_at, kept);
  `npm run index -- --supervision` re-asks only that. A repository with no new activity keeps its
  answer. The curated snapshot and the index must agree; `data/recent.json` and the /work/
  pages carry the same answer, and read commits, languages and READMEs through the same layer.
- A `GITLAB_TOKEN` that is not one line, or that GitLab refuses, is dropped with a log line and the
  refresh reads anonymously; a bad secret never costs the refresh.
- `npm run data` (`scripts/fetch-github.mjs`) writes `data/github.json`: profile, contribution
  calendar, languages, per-project facts (stars, language, push date, live HTTP status,
  supervision) and the Majordomus release from `majordomus.dev/build.json`, with `generated_at`.
- Every page that shows a figure shows the snapshot date; `/stack/#data` names each source.
- Only original public work is listed: no forks, no mirrors.
- `npm run index` (`scripts/fetch-index.mjs`, through the `gh` and `glab` CLIs) writes
  `data/index.json`: every public repository on GitHub and GitLab, merged by name. A repository is
  listed as original only when it is not a fork, the owner wrote at least half of its listed
  commits, its description does not say it is someone else's code, and it is not on the
  owner-curated `[index] mirrors` or `hidden` lists in `data/projects.toml`. Everything else is
  counted and the counts are shown. Its category is inferred from the declarative `keywords` and
  `languages` of `[categories.*]`; `npm run index -- --derive` re-derives offline.
- Skills on the about page are derived with their evidence (languages from the index,
  technologies from the curated stacks, domains from the categories); none is typed.
- `static/llms.txt` and `static/llms-full.txt` are generated by `scripts/build-llms.mjs`.
- The site's machine interfaces are derived by `scripts/build-interfaces.mjs`: `static/ai.json` is
  Majordomus's own index of `.ai/` (`majordomus run objects.list`, `capabilities.list`), stamped
  with the tracked `.ai/` tree, so a change to `.ai/` that was not indexed again fails offline;
  `static/openapi.json` describes every published machine-readable file, each summary read from
  the file. /interfaces/ and the topbar's interfaces menu render only these two files.

# Failure behaviour

`scripts/check-data.mjs` exits 1 on a malformed catalogue, a project missing from the snapshot,
a fork, a private repository, a dead live URL, a hand-typed Majordomus, a listed repository with
no supervision answer, an index measured for another marker, or a curated project whose
supervision differs between `data/github.json` and `data/index.json`; `build-llms.mjs --check`
exits 1 on a stale `llms.txt`.

# Verification

```sh
node scripts/check-data.mjs
node scripts/build-llms.mjs --check
```
