The catalogue has two layers. A handful of projects are featured: chosen by the owner and described in their own words. Everything else is classified automatically, so the catalogue grows with the work and never needs tending.

Each category is a rule rather than a folder. A [repository](@/glossary/repository.md) lands in a category when its name, description or topics match the rule's keywords, otherwise its primary language decides. That is how supervision of [AI agents](@/glossary/ai-agent.md), [OSINT](@/glossary/osint.md) cases, [GIS](@/glossary/gis.md) catalogues and [data visualisation](@/glossary/data-visualisation.md) end up side by side without anyone sorting them.

Each category page explains itself in the same way, and every project links to its [open-source](@/glossary/open-source.md) code.
