# korczis.github.io

The personal hub of Tomas Korcak (korczis): <https://korczis.github.io/>. It covers who I am,
the projects I build with their live sites, the stack behind them, and
[Majordomus](https://majordomus.dev), which supervises the work.

The site uses Zola (Tera 2) with Flowbite Pro on Tailwind 4, Alpine.js, Cytoscape.js, Apache
ECharts, Chart.js and p5.js. It is supervised by Majordomus and deployed to GitHub Pages from
`master`. The decision is recorded in
[ADR 0001](.ai/repo/adrs/0001-personal-hub-on-zola-with-flowbite-pro-deployed-to-github-pa.md).

## Quick start

```sh
npm install          # also points git at .githooks (doctor on commit, finish --check on push)
npm run dev          # vendor bundles + CSS, then zola serve on http://127.0.0.1:1111
npm run verify       # every gate CI runs, browser audit last (-- --fast skips the browser)
```

You need Node 22 and Zola `0.23.4` (`.zola-version`). For the hooks and the `doctor` gate you
also need [majordomus](https://majordomus.dev).

## Languages

The site exists in English and Czech (`/cs/`) through Zola's multilingual features:
- **Interface texts:** `i18n/strings.toml` holds every text, with an `en` and a `cs` value per
  key. `npm run i18n` writes it into `zola.toml` and templates call `trans()`.
- **Data:** every text field has a `_cs` twin, read generically as `c["name" ~ sfx]`.
- **Pages:** every page is `x.md` plus `x.cs.md`. The generators write both versions of the
  category and work pages.
- **Tags:** tags are a Zola taxonomy, derived from categories and languages.
- **The gate:** `scripts/check-i18n.mjs` fails on any untranslated text (rule
  `project.i18n-everywhere`).

## Every page is an article

Each page also teaches: it carries an article (its Markdown body) that explains what it shows and
how to read it, and ends with **Concepts on this page**, the glossary terms it builds on.
- **Glossary:** `data/glossary.toml` defines each term (language, technology, concept) in English
  and Czech, with a source to read further. `npm run glossary` writes `content/glossary/`: one
  page per term and language, listing every page that uses it and the related terms. Both lists
  are derived from front matter.
- **Front matter:** `extra.terms` names a page's terms, and `extra.article_title` names its
  article. Generated pages get both from their generator (`scripts/lib/terms.mjs` resolves
  languages, stack and categories to terms by convention). Hand pages write them in `content/`.
- **Links:** articles link to terms with `@/glossary/<id>.md`, so Zola checks every link.
- **Machines:** JSON-LD `about` lists a page's terms as `DefinedTerm`, and term pages belong to
  the glossary's `DefinedTermSet`.
- **The gate:** `scripts/check-glossary.mjs` fails on a page without an article or terms, on an
  unknown or unused term, and on a term without a source (rule `project.pages-are-articles`).

## How the site stays current

Pages are front matter over data. Nothing on them is typed, so nothing needs updating by hand:
- **Front matter:** `content/*.md` carries it, checked against
  [`static/schemas/front-matter.schema.json`](static/schemas/front-matter.schema.json).
- **Data:** `data/projects.toml` holds the words. `data/github.json` and `data/index.json` hold
  the measurements.
- **Derived:** category pages, `llms.txt`, `llms-full.txt`, OG images and `site.json` (the whole
  site as data).
- **Weekly refresh:** `.github/workflows/refresh.yml` runs every Monday, or by hand with
  `gh workflow run refresh.yml`. It runs `npm run refresh`, then `npm run check`. Only when every
  gate passes does it commit to master and start the deploy.

## Common tasks

- **Add a project.** Add an entry to `data/projects.toml`, then run `npm run data`, `npm run categories`, `npm run llms` and `npm run og`.
  `check-data.mjs` refuses forks, private repositories, dead live URLs and a hand-typed
  "Majordomus" in `stack`.
- **Refresh the numbers.** Run `npm run data` and `npm run index` (they need authenticated `gh` and
  `glab`), then `npm run categories`, `npm run llms` and `npm run og`. Commit the results. Every page shows the date of its snapshot.
- **Change a category rule or the mirrors/hidden lists.** Edit `data/projects.toml` and run
  `npm run index -- --derive`. No network is needed.
- **Add a visual.** Create `static/js/viz/<name>.js` registering `KorczisHub.viz('<name>', …)`,
  put `data-viz="<name>"` on a box that reserves its size, and load the script from the
  template. `check-viz-layer.mjs` enforces the layer.
- **Add a page.** Add the template and a `content/` entry with `title`, `description` and
  `[extra] og_title`, `og_image`, `schema` and `keywords`. Run `npm run og` and add the page to
  `PAGES` in `scripts/audit-ui.mjs`. Titles, Open Graph and Twitter tags and JSON-LD are derived
  from that front matter.

## Deploy

A push to `master` runs `.github/workflows/pages.yml` in three stages:

1. `ci`: the same workflow pull requests run.
2. `deploy`: deploys the validated artefact to Pages.
3. `verify`: checks that production serves `revision.txt` equal to the commit and smoke-tests
   every page and asset. It then runs the same browser audit against the public site and asks
   every linked live project whether it answers.

`.github/workflows/monitor.yml` repeats that production check every day, and you can also start
it by hand from the Actions tab.

The repository is public and declares `ui.kit: flowbite-pro`. Because of that, CI's
`majordomus doctor` fails closed until the owner stores the licence evidence. Do it once:

```sh
~/.claude/skills/flowbite-pro/evidence.sh secret | \
  gh secret set MAJORDOMUS_KIT_EVIDENCE_FLOWBITE_PRO -R korczis/korczis.github.io
```

## Repository settings

These are set through the GitHub API (`gh api`), not in files:
- description, homepage and topics;
- wiki, projects and discussions are off; branches are deleted on merge; auto-merge is allowed;
- Pages: `build_type: workflow`, HTTPS enforced;
- secret scanning with push protection, Dependabot alerts and security fixes (and
  `.github/dependabot.yml` for weekly grouped updates);
- ruleset "master: history is append-only", which blocks deleting `master` and force-pushing to it;
- secret `MAJORDOMUS_KIT_EVIDENCE_FLOWBITE_PRO`; optional variable `PAGES_RUNNER` (ADR 0002).

## Working on this repository

The repository is supervised by Majordomus. AI workers start from [`AGENTS.md`](AGENTS.md)
(Claude Code: `CLAUDE.md`, Gemini: `GEMINI.md`, all generated from `.ai/repo/policy.yaml`). They
run `majordomus context` and work in a branch under `korczis.github.io-wt/<branch>`
(`majordomus worktree create <branch>`). A task closes with `majordomus finish` once
`npm run verify` has passed.
